# RedVeil — پنل مدیریت VLESS با دیزاین دارک/قرمز شیشه‌ای

پنل مدیریت کاربران VLESS+WS مبتنی بر Xray-core، با معماری تک‌پورتی برای Railway
(nginx یک پورت عمومی را بین پنل وب و اینباند پروکسی مالتی‌پلکس می‌کند — دقیقاً مثل معماری RVG).

## قابلیت‌ها

- ✅ لاگین امن (session + bcrypt)
- ✅ مدیریت کامل کلاینت‌ها: ساخت / ویرایش / حذف / فعال‌سازی، محدودیت حجم، تاریخ انقضا
- ✅ تولید خودکار کانفیگ Xray و ری‌استارت هسته با هر تغییر
- ✅ صفحه ساب‌اسکریپشن اختصاصی هر کلاینت با QR Code و دیزاین دارک/قرمز شیشه‌ای
- ✅ لینک ساب استاندارد (base64) سازگار با v2rayNG / Hiddify / NekoBox
- ✅ صفحه لاگ زنده Xray در پنل
- ⚠️ آمار ترافیک لحظه‌ای هنوز به Stats API واقعی Xray وصل نشده (اسکلت آماده است — بخش «توسعه بعدی» را ببینید)
- ⚠️ فقط یک Inbound پشتیبانی می‌شود (نه چند اینباند هم‌زمان)

## دیپلوی روی Railway

1. این پوشه را در یک ریپازیتوری گیت‌هاب (خصوصی یا عمومی) قرار بده و push کن
2. در Railway: **New Project → Deploy from GitHub repo** → همین ریپو را انتخاب کن
3. Railway به‌صورت خودکار `Dockerfile` را تشخیص و بیلد می‌کند
4. متغیرهای محیطی زیر را در بخش **Variables** تنظیم کن:

   | متغیر | مقدار پیشنهادی |
   |---|---|
   | `ADMIN_USER` | یوزرنیم دلخواه ادمین |
   | `ADMIN_PASS` | رمز عبور اولیه (حتماً بعداً از پنل عوضش کن) |
   | `SESSION_SECRET` | یک رشتهٔ رندوم و طولانی |
   | `WS_PATH` | مسیر وب‌سوکت، پیش‌فرض `/cdn` |

5. از بخش **Settings → Volumes** یک Volume به مسیر `/data` وصل کن (وگرنه با هر Redeploy، کاربران و دیتابیس پاک می‌شود)
6. از **Settings → Networking → Generate Domain** یک دامنه عمومی بگیر
7. وارد پنل شو (`https://دامنه‌شما.up.railway.app`)، از تنظیمات پنل، «دامنه ساب» را همان دامنه‌ی Railway‌ات قرار بده و ذخیره کن
8. یک کلاینت جدید بساز و لینک `/sub/...` را برای اتصال استفاده کن

## نکات مهم

- اگر بعداً `WS_PATH` را از داخل پنل عوض کنی، باید متغیر محیطی `WS_PATH` در Railway را هم با همان مقدار هماهنگ کرده و Redeploy کنی — چون nginx مسیر را در زمان استارت کانتینر می‌خواند، نه به‌صورت پویا
- یوزر/پسورد پیش‌فرض از env گرفته می‌شود؛ اگر تنظیم نکنی، مقدار پیش‌فرض `admin/admin` است — حتماً از پنل عوضش کن

## توسعهٔ بعدی (پیشنهادی)

- اتصال به Xray Stats API (gRPC) برای آمار ترافیک لحظه‌ای دقیق به‌جای شمارش تقریبی
- پشتیبانی از چند Inbound هم‌زمان (نیاز به روتینگ پویای nginx بر اساس مسیر)
- پشتیبانی از پروتکل‌های VMess / Trojan / Reality
- اعلان تلگرام برای نزدیک‌شدن به سقف مصرف یا انقضا

## اجرای محلی (تست بدون Xray واقعی)

```bash
npm install
ADMIN_USER=admin ADMIN_PASS=admin PANEL_PORT=3000 node server.js
```

اگر باینری `xray` روی سیستم نباشد، پنل در «حالت فقط-مدیریت» بالا می‌آید (بدون پروکسی واقعی) تا بتوانی UI را تست کنی.
